# Model fallback and token-limit recovery
When a provider reports rate limiting, exhausted quota, or a context/token limit, do not claim the request succeeded. The server may retry configured fallback models. If the context is too long, summarize only non-sensitive task context and retry once when the application supports it. Never ask the user to paste API keys into chat or send credentials to a model. Explain when no configured fallback is available. Provider quota failover requires a separately configured credential or provider; switching model IDs alone cannot restore an exhausted account quota.
