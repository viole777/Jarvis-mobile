# Jarvis acceptance test plan

This plan is the release gate for the cloud worker, browser UI, voice, device bridges, and Android app. A test is PASS only with a recorded observable result; an assistant's self-report is not evidence.

## Execution rules
- Run static checks and isolated unit tests on every push.
- Run integration tests against a disposable/test environment first.
- Do not run destructive tests against production accounts or real devices.
- Never print secrets, tokens, full headers, or personal screen contents in CI logs.
- Tests that need microphone, browser permissions, a paired device, or manual consent are marked MANUAL and cannot be auto-passed.
- Production deploy requires all CI checks to pass and an explicit deployment workflow invocation.

## Gate A — source integrity and security
- A01: Worker JavaScript parses with Node.js.
- A02: Android Kotlin compilation succeeds.
- A03: No API keys or access tokens are committed to source, HTML, test fixtures, or logs.
- A04: Protected routes reject missing and invalid authentication.
- A05: CORS permits only explicitly configured trusted origins; arbitrary origins are rejected.
- A06: Requests are size-limited and invalid JSON returns a safe 4xx response.
- A07: Errors do not expose stack traces, secrets, internal IP addresses, or environment values.
- A08: Device bridge requires a valid pairing identity and signed/authorized commands.
- A09: Destructive or external side-effect actions require explicit confirmation.
- A10: Replay, expired pairing, and revoked pairing are rejected.

## Gate B — backend and provider routing
- B01: /v2/status returns valid JSON without secrets.
- B02: /v2/chat rejects empty/oversized messages and accepts valid Portuguese text.
- B03: Provider timeout/failure falls back cleanly and returns an honest provider/model label.
- B04: Model label is derived from the provider actually used, not generated by the model.
- B05: Conversation context is isolated by authenticated user/session.
- B06: Memory CRUD persists across requests and does not leak across sessions.
- B07: Task creation, listing, completion, and planning validate inputs.
- B08: Rate limiting prevents uncontrolled request floods.
- B09: Tool arguments are schema-validated and allow-listed; model output alone cannot authorize arbitrary code execution.
- B10: Backend returns actionable errors without falsely claiming task completion.

## Gate C — browser UI
- C01: Main page loads on mobile and desktop sizes with no uncaught JS errors.
- C02: Connect/disconnect states are clear; secrets are not persisted in localStorage.
- C03: Sending text appends user and assistant messages once and scrolls to latest.
- C04: Enter sends; Shift+Enter adds a newline.
- C05: Loading, failure, timeout, and retry states work.
- C06: Layout is usable at 320px width and desktop 1280px.
- C07: Clear chat clears only the visible transcript, not server memory.
- C08: Buttons and form controls have labels and keyboard focus states.
- C09: Status and model labels match backend observations.

## Gate D — voice conversation
- D01: Microphone permission denial is handled and explained.
- D02: Voice activation starts listening only after user gesture.
- D03: Speech is transcribed in pt-BR and sent once.
- D04: Partial transcription is visible without being submitted early.
- D05: Jarvis response uses the same conversation thread as typed messages.
- D06: Listening does not restart while response audio is playing.
- D07: Stop button stops listening and speech output.
- D08: Unsupported browser speech APIs show a useful fallback.
- D09: Repeated recognition errors do not create runaway restart loops.
- D10: Manual test confirms echo does not cause Jarvis to answer itself; headset and speaker modes checked.
- D11: Voice playback can be interrupted by the user.
- D12: Optional expressive TTS failure falls back gracefully without losing the text response.

## Gate E — browser/computer bridge
- E01: Web app can pair with a named desktop agent using a one-time approval code.
- E02: Unpaired clients cannot read screenshots or execute commands.
- E03: Screenshot capture occurs only after permission and explicit request.
- E04: Click/type/navigation commands are restricted to allow-listed operations and visible session.
- E05: Browser bridge cannot access arbitrary local files or execute shell commands by default.
- E06: High-impact actions show a confirmation with a human-readable summary.
- E07: Disconnect/revoke immediately blocks future commands.
- E08: Network loss is surfaced and commands are not reported as completed.
- E09: No remote desktop/browser action is claimed successful without agent acknowledgement.
- E10: MANUAL: verify a real browser tab with consent; then verify OS-level actions only on a test machine.

## Gate F — Android bridge
- F01: App builds and installs.
- F02: Accessibility service is off by default and enablement is user-controlled.
- F03: Commands are rejected if service permission is absent.
- F04: Screen inspection redacts sensitive fields where possible.
- F05: Tap/text/navigation operate only on supported visible nodes and report failures.
- F06: Device pairing is authenticated; revoked/expired pairing is rejected.
- F07: User can stop automation immediately.
- F08: MANUAL: test on a non-sensitive screen; never automate banking, password, or payment flows.

## Gate G — release and operations
- G01: All automated CI jobs pass on the exact commit being released.
- G02: Worker deployment uses preserved bindings/secrets and correct compatibility settings.
- G03: Post-deploy smoke tests validate status, auth, chat, and version marker.
- G04: Rollback version is identified and recoverable.
- G05: Logs are useful but redact user text, secrets, and sensitive screen contents.
- G06: Android APK artifact is built and downloadable from CI.
- G07: Manual-only tests remain visibly MANUAL until a person records results.
